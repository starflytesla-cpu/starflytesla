# 03 · VPS 配置建議

> 以下數字是依公開資料和常見 FFmpeg 效能推估的，**上線前要用真實素材壓測**（見第 5 節）。

## 1. 吃資源的是哪一段？

| 環節 | 吃什麼 | 說明 |
| --- | --- | --- |
| 渲染（FFmpeg 編碼） | **CPU** | 最大的瓶頸。libx264 可以用滿多核心 |
| 素材轉碼（proxy） | CPU | 每支上傳的素材都要轉一次 |
| 鏡頭偵測、抽幀 | CPU | 負載輕 |
| 語音轉文字（faster-whisper） | CPU / GPU | small 模型在 CPU 上可接受 |
| 多模態打標籤、LLM 文案 | **外部 API** | 呼叫雲端模型的話，VPS 幾乎不耗資源；自架模型才需要 GPU |
| 原始素材與成片 | **磁碟 / 物件儲存** | 成長最快的是容量 |
| 手機上傳、發佈到平台 | 頻寬 / 流量 | 上傳是入站流量，發佈是出站流量 |

結論：**AI 部分先用 API，VPS 不需要 GPU；主要買 CPU 核心數和儲存空間。**

## 2. 容量估算

假設：

- 手機 1080p 原片約 40～60 MB/分鐘（4K 約 3～4 倍）。
- 每家工廠每天上傳約 15 分鐘素材 → 約 0.6～0.9 GB/天 → **約 20～27 GB/月**。
- 成片 30 秒、約 8 Mbps → **約 30 MB/支**。
- 渲染 30 秒 1080×1920 影片（含縮放、字幕、轉場濾鏡），4 vCPU 約需 0.5～1.5 分鐘。

| 規模 | 素材增量 / 月 | 成片 / 天 | 渲染 CPU 需求 |
| --- | --- | --- | --- |
| 試點：1～3 家 | 約 80 GB | 約 30 支 | 4 vCPU 綽綽有餘 |
| 小規模：10 家 | 約 270 GB | 約 100～200 支 | 8 vCPU |
| 中規模：30～50 家 | 1 TB 以上 | 500 支以上 | 需要多台渲染節點 |

所以**儲存一定要規劃成物件儲存**（MinIO → 之後換成 R2 / OSS / S3），並設定生命週期：分析完成後把原片壓縮成中間檔，或在 N 天後轉到低頻儲存。

## 3. 配置建議

| 等級 | vCPU | 記憶體 | 系統碟 | 素材儲存 | 頻寬 | 適用 |
| --- | --- | --- | --- | --- | --- | --- |
| **入門（MVP）** | 4 | 8 GB | 160 GB NVMe | 本機 MinIO | 100 Mbps 以上 | 開發、1～3 家試點 |
| **推薦（正式上線）** | 8（**獨享 CPU**） | 16～32 GB | 200 GB NVMe | 外接物件儲存 1 TB 起 | 200 Mbps～1 Gbps，流量大或不限量 | 約 10～20 家、每天幾百支成片 |
| **單機上限** | 16（獨享） | 32～64 GB | 400 GB NVMe | 物件儲存 | 1 Gbps | 單機再往上，性價比就很差了 |
| **擴展（不再升單機）** | 主機 4C8G + N 台 8C16G 渲染節點 | | | 物件儲存 | | 50 家以上：水平擴充渲染 worker |
| **選配：GPU** | + NVIDIA L4 / T4 等級 | | | | | 只有在自架多模態模型 / TTS，或要用 NVENC 大量編碼時才需要 |

### 關於「最多需要什麼配置」

- **單台 VPS 做到 16 vCPU / 64 GB 就是合理上限。** 再往上應該把渲染拆成多台 worker（架構上已經用佇列解耦），而不是繼續買更大的單機。
- **正式服務多個帳號群時，用「推薦」等級：8 vCPU（獨享）/ 16 GB / 200 GB NVMe + 物件儲存。** 要選「獨享 / dedicated CPU」。共享 vCPU 在長時間編碼時會被限速，渲染時間會很不穩定。只有一個帳號群的起步期，用入門規格即可（見第 4 節）。
- 初期**不需要 GPU**；GPU 伺服器價格通常是同級 CPU 機器的好幾倍。

## 4. 機房位置

> **已決定：目標是海外平台 → 建議使用新加坡機房。** 對亞洲的拍攝端上傳速度較好，連到 BytePlus（東南亞區）、DeepSeek、OpenRouter、Upload-Post 的延遲也都可以接受。起步只有一個帳號群（每天約 15 支成片），**用 4 vCPU / 8 GB 就足夠**；試營運數據穩定、開始增加帳號群時，再升級到 8 vCPU 獨享 CPU。

| 目標平台 | 建議 |
| --- | --- |
| 中國大陸（抖音、快手、小紅書、視頻號） | 阿里雲 / 騰訊雲大陸機房，需要 **ICP 備案**；或使用香港機房（免備案，但連大陸的速度可能不穩定） |
| 海外（TikTok、IG、YouTube、FB） | 新加坡 / 日本 / 美西，例如 Hetzner、Vultr、DigitalOcean、AWS Lightsail |
| 兩邊都要 | 香港 / 新加坡主站，國內平台的發佈節點另外部署 |

## 5. 壓測計畫（MVP 完成後）

1. 準備 20 支真實工廠素材（直式 / 橫式、1080p / 4K 混合）。
2. 在候選 VPS 上用 `render` worker 連續渲染 50 支 30 秒成片，記錄平均 / P95 耗時與 CPU 使用率。
3. 用每支成片的耗時反推每台節點每小時的產能，再決定規格與節點數量。
