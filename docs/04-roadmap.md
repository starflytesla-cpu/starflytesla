# 04 · 執行方案（草稿，待確認）

## 待確認問題（會影響方案）

1. **目標平台**：先做國內（抖音 / 快手 / 小紅書 / 視頻號）還是海外（TikTok / IG / YouTube / FB）？還是兩邊都要？
2. **商業模式**：只給自己的客戶用（代營運），還是做成 SaaS 讓工廠自己註冊？這會決定多租戶、計費、權限要做多完整。
3. **AI 服務商**：有沒有偏好或已有帳號？（通義千問 / 豆包 / DeepSeek / OpenAI / Claude / Gemini）國內平台的內容建議用國內模型。
4. **人工審核**：成片要人工確認後才發佈，還是允許全自動發佈？（建議初期保留人工確認）
5. **預算**：VPS 與 API 的每月預算上限，以及第一批試點客戶數。

## 階段規劃

### Phase 0：基礎建設（約 1 週）

- [x] 專案骨架、調研、架構文件
- [ ] Docker Compose：PostgreSQL + pgvector、Redis、MinIO、tusd、Caddy
- [ ] FastAPI 骨架、資料庫遷移（Alembic）、登入與租戶
- [ ] 前端骨架（PWA）、CI（lint + test）

### Phase 1：拍攝上傳與素材庫（約 2 週）

- [ ] 手機拍攝 / 選檔 → Uppy + tus 斷點續傳
- [ ] `analyze` worker：ffprobe、proxy 轉碼、縮圖、PySceneDetect 切片
- [ ] 多模態模型打標籤 + 自動分類；素材庫可以篩選、預覽、人工修正標籤
- [ ] 嵌入向量 + 重複素材偵測

**驗收**：在工廠現場用手機上傳 10 支影片，5 分鐘內在素材庫看到切好、標好的片段。

### Phase 2：帳號檔案、模板、文案（約 1～2 週）

- [ ] 帳號檔案 CRUD（對應截圖中的「帳號檔案」）
- [ ] 內建行業模板（人設型 / 流量型 / 成交型）+ 自訂模板
- [ ] LLM 按人設一鍵改寫鏡頭文案，可產生多個版本
- [ ] 音色管理：TTS 音色選擇與試聽

### Phase 3：混剪引擎（約 2～3 週）

- [ ] 時間軸 JSON 規格
- [ ] 鏡頭 → 素材自動匹配（向量檢索 + 規則 + 去重）
- [ ] TTS 配音、字幕（ASS）、BGM、轉場，用 FFmpeg 合成 9:16 成片
- [ ] 批量產出 N 個差異化版本；作品庫預覽與人工確認
- [ ] 在目標 VPS 上壓測（見 03-vps-sizing.md 第 5 節）

**驗收**：選一個模板 + 一個帳號檔案，一鍵產生 5 支彼此不重複、可以直接發佈的成片。

### Phase 4：發佈與評論（約 2 週）

- [ ] `PublisherAdapter` 介面 + 第一個實作（依待確認問題 1 決定是 Upload-Post 還是抖音開放平台）
- [ ] 發佈帳號管理（OAuth 授權、token 加密儲存）
- [ ] 發佈任務：排程、失敗重試、狀態回寫
- [ ] 評論拉取、LLM 分類、建議回覆、一鍵回覆

### Phase 5：試點與迭代

- [ ] 1～3 家工廠試點，收集回饋
- [ ] 數據面板（播放、按讚、評論、詢價數）
- [ ] 依壓測結果調整 VPS 規格，或拆出渲染節點

總計約 **8～10 週**達到可試點的 MVP（以 1～2 名全端工程師估算）。
